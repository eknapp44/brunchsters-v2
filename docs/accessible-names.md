# Accessible names changed on purpose

The e2e journeys find controls by role and accessible name, so a rename is a contract change
(`apps/web/CLAUDE.md`, "Accessible names are a contract"). This file is the log: what each spec
renamed, so a journey that breaks on a name can be traced to the decision. Add to it when you rename
something; list the journeys you edited in the spec's `tasks.md`.

## Spec 0011, design fidelity

Dashboard (M2): the h1 `Dashboard` is now the greeting ("Morning, Evan"; "Hey, Evan" until the browser has filled the time in), so journeys wait on `expectDashboard` (`e2e/support/dashboard.ts`), never on one word of it; `No brunches yet.` is "The table's set. Now invite some people." (`EMPTY_DASHBOARD_HEADLINE`); rows and the next-up card word the status "Open for votes" / "In the works" (the brunch page badge keeps the lookup label); the next-up brunch is a card (`h2` = its title, a link "Open <title>"), not a row, and is not repeated in the list. Unchanged: `Plan a Brunch`, `Upcoming`, `Past`, the title link, `(Host)`, `N going`. Brunch page (M3): the RSVP buttons are `I'm in` / `Maybe` / `Can't` (in that order; the emoji are `aria-hidden`), the card heading is `You in?`, the ballots are `Where to?` and `When?` (the manage page keeps `Locations` and `Times`, so journeys use `ballot()` on the brunch page and `manageOptions()` on the manage page), the host's invite button is `Round up the crew`, and a confirmed brunch shows a `Brunch on.` heading and two `Locked in` chips. The status badge still reads exactly "Active", "Draft" or "Confirmed" once. "Who's coming" is plain grouped text (`role="group"`), not a list; a pending person's address appears in it and in the invite list, so a journey that means the invite list uses `inviteRow`. Creation wizard (M4): the main button of steps 1 to 3 is `Continue` (was `Next`; the page object's `next()` clicks it), the first step's progress name is `Title` (was `What`), each step has an `h2` heading (`Give it a name`, `Pick a spot`, `Pick a time`, `Round up the crew`) with an eyebrow "Step N of 4 · …", and `Cancel` is a link (top, left out on a phone, and in the first step's footer). `Plan a Brunch` is still the page `h1`. Front door and edges (M5): the landing page and the sign-in page share the h1 "Your friends are hungry. Probably." (journeys use `expectLandingPage` / `expectSignInPage` in `e2e/support/pages.ts`, which also look for something only that page has), the landing page's links are `Round up the crew`, `See how` and a small `Sign in`, the invite preview's h1 is the brunch title with "{host} wants you at brunch" above it (no status badge), an unusable invite says "That invite's gone cold.", every 404 says "This table's empty." and nothing more (it must never say "brunch", "private" or why), and the host's manage buttons are `Close voting` (was `Call it` until spec 0013, which renamed it so it is no longer a substring of `Call it off`) and `Lock it in`. After M7: a member who is not the host opening the manage page gets a **403** with the h1 "That one's the host's." (`HOST_ONLY` in `e2e/support/pages.ts`), while an outsider still gets the 404 text. Later milestones add their changes here.

## Spec 0013, brunch lifecycle

Manage page: an `End of the road` section with `Call it off` (dialog confirm; the safe button `Nope, keep it` has focus), `Bring it back`, and `Delete this brunch` / `Delete this draft` (dialog confirm `Delete it`, safe button `Keep it`); a called-off brunch's page has a `Called off.` banner and no RSVP, ballots or suggestion controls. `Hide from my dashboard` / `Unhide` on the brunch page, `Hide {title}` / `Unhide {title}` as an eye icon on dashboard rows, the next-up card and the Hidden list (the name is on the button and is its tooltip; the brunch page's header keeps the word), a `Hidden (n)` link and a `Show all` link for the Past cap. Close voting is `Close voting`, not `Call it`, so neither manage-page button name contains the other.

Later changes in the same spec: the manage page's close-voting button is **Close voting** (it was
**Call it** from spec 0011 until 0013, when it was renamed because it was a substring of **Call it
off**), and its nudge line says "close voting now if you're ready". The brunch page's Hide control is
in the header beside Manage brunch; on dashboard rows, the next-up card and the Hidden list it is an
eye icon whose `aria-label` and tooltip are `Hide <title>` / `Unhide <title>`.

## Spec 0014, feedback surfaces

No button, link, label or heading is renamed. What changes is the error and result text, and the role it sits in (a failure that was a `role="alert"` line under a control becomes a toast in one polite `status` region, or stays an inline `alert` where the person must fix or wait it out).

- **M2, RSVP:** the "Failed to update RSVP" `alert` under the buttons is gone; a failure toasts "Something went sideways on our end." (or the line for the code the route sent, for example "This one's been called off, so it can't change."), and a success toasts "You're in. See you there." / "Maybe it is. You can change it any time." / "Got it, you can't make it." New: the toast region (`role="status"`, `aria-live="polite"`, always present, empty until a toast) and a **Dismiss** button on each toast. The RSVP buttons (**I'm in**, **Maybe**, **Can't**) keep their names; while a save is out they are `aria-disabled` instead of `disabled`, so keyboard focus stays on the button that was pressed. Journey edited: P6 in `brunch-page.spec.ts`; new: T1 and T2 in `feedback.spec.ts` (words in `e2e/support/toasts.ts`).
